# Credential handling

API keys are credentials, not world content or ordinary provider preferences. Provider settings and task route snapshots contain connection IDs, protocol, endpoint and model IDs only. Status APIs return IDs with saved keys, never the key values.

## Android

- AES-GCM encrypts each API key with the `voyage-api` key generated by Android Keystore. The encryption key is non-exportable; hardware backing depends on the device and is not promised by the app.
- Only IVs and authenticated ciphertext are written to private `secrets` preferences. Android Keystore holds cryptographic keys, rather than arbitrary provider-token strings, so encrypted ciphertext still requires local storage.
- New entries bind ciphertext to the credential name with GCM additional authenticated data. Older encrypted entries remain readable so upgrading does not discard saved keys.
- Encryption/decryption failures do not fall back to plaintext or silently create a replacement key for unreadable ciphertext. Failed persistent writes are reported rather than announcing success.
- Empty-key removal deletes the stored entry. Saving removal of a provider connection removes its saved credential. Unknown provider IDs are rejected by the key-write endpoint.
- App backup is disabled. Explicit cloud-backup and device-transfer rules also exclude `secrets.xml` and the agent's `provider` home, which may contain login credentials.
- Password inputs do not populate saved plaintext keys, enable spellcheck or auto-capitalization. Entered keys remain transient UI state until connected and are then cleared.

## Desktop and development preview

The desktop host uses Electron safeStorage when a supported secure backend is available; insecure Linux `basic_text` storage is rejected. Without a secure backend, keys are session-only and the UI says so. The development browser uses its host's credential policy; it is not proof of Android Keystore behavior.

## Boundaries

Keys must exist briefly in runtime memory to authenticate authorized provider requests. This is not a promise of protection against a rooted device, a compromised app process, screenshots of entered text, or a malicious endpoint deliberately configured by the user. Do not put keys in exports, logs, model prompts, project JSON, route snapshots or localStorage. Connection tests are explicit and may cost money; startup refresh only reads status.

Removing a stored key does not revoke it at the provider. Revoke compromised credentials in the provider's account controls.
